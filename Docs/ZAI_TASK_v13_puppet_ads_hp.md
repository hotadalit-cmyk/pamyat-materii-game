Задача v0.13 — четыре части. Этап 2 принят: zai/guardians-v12 влит, Unity собрался с первого раза. Отличная работа!

## База
Та же песочница: `git checkout zai/guardians-v12 && git checkout -b zai/v13`. Правила прежние (C# 9, без LINQ/System.Random,
детерминизм, Domain без UnityEngine, без .meta, без push, старые тесты не ослаблять, коммиты по ходу, отчёт ≤ 15 строк).
Будь внимателен к Vec2 (Domain) / Vector2 (Unity). Unity я компилирую у себя.

## 1. Тестовый старт у стража (для проверки боёв)
- `DevTools.Enabled` (const bool = true; перед релизом выключу) — в Systems.
- Настройки (RunSettings) → секция «Для тестов» (видна только при DevTools.Enabled): кнопки «Страж 1»…«Страж 5».
- Нажатие: новая жизнь в открытом мире сразу на глубине N; масса героя = GoalMass глубины × 1.1, RoomAbsorbed = GoalMass
  (страж просыпается сразу), герой стоит в ~6 ед. от шахты, 2 жетона эволюции, по 20 каждого ресурса.
  Domain: `RunState.CreateDevGuardianRun(SoulMeta meta, ulong seed, int depth)` (статическая фабрика), тест на неё.

## 2. Кольцо HP вокруг противников
- Domain: у существа в Unity есть `Mass`; добавь `MaxMass` (масса при спавне, растёт, если существо ест/растёт).
- Unity: вокруг каждого не-съедобного существа (не спора) — тонкая дуга-шкала HP снаружи кольца угрозы:
  заполнение = Mass / MaxMass по часовой стрелке от верха. Показывать, когда существо ранено (< 99%) или у стражей/капель Горнила — всегда.
  Цвет: зелёный > 60%, жёлтый 30–60%, красный < 30%. Реализация: 32 закэшированных спрайта-дуги (процедурные Texture2D),
  выбор спрайта по доле — без шейдеров и без аллокаций в кадре. Скрывать вместе с существом (спит/вне экрана).
  HP-полоса стража в RunUi остаётся.

## 3. Навык «Марионетка» — продвинутый автопилот
Ветка эволюции «Клоны» (EvolutionTree), два новых узла:
- `puppet` «Марионетка» (способность `Abil("puppet")`, требует `clone_instinct`): кнопка умения «Авто» (SkillButton по дуге справа, как «Деление»),
  включает продвинутый автопилот ГЕРОЯ. Касание джойстика/рогатки сразу отдаёт управление игроку на 3 с, потом автопилот продолжает.
  Повторное нажатие «Авто» — выключить. Пауза/модальные окна — автопилот стоит.
- `puppet_master` «Кукловод» (требует `puppet`, `clone_soul`): тап по клону в мире — выдать/снять ему продвинутый автопилот
  (макс. 2 клона; над ним маленькая золотая метка-нить). Клоны без метки играют как раньше (TwinForage).
- Domain: `PuppetBrain` — чистая функция решения:
  вход: позиция/масса/скорость себя, заряды рывка, видимые существа (позиция, масса, IsFood, IsShimmering, угроза = могут ли ранить),
  опасные зоны/телеграфы стража (круги), ноша (для клона), позиция лидера и дальность связи;
  выход: направление движения (Vec2), `Dash` (bool) + направление рывка, `Intent` (Hunt/Flee/Graze/Return/Avoid) — для подписи.
  Правила: бежать от тех, кто ранит (кольцо красное), если они ближе 4; обходить зоны/телеграфы; охотиться на самую выгодную цель
  (масса × мерцание ×1.5 / дистанция), которую можно съесть; рывок — когда цель на линии 2–6 ед. и заряд есть (оставлять 1 заряд на побег);
  клон с ношей > 60% ёмкости или у края связи — возвращается к лидеру; если ничего нет — пасётся (споры). Детерминизм.
- Тесты `PuppetTests.cs`: бегство от крупного, выбор выгодной цели, мерцающая предпочтительнее, обход зоны, рывок только с запасом,
  возврат клона с ношей/у края связи, узлы эволюции puppet/puppet_master и их требования.
- Unity: героя с автопилотом двигать через тот же путь, что и джойстик (JoystickStep/рывок через OnDashRelease), клонов с меткой — силой
  как в TwinForage, но по решению PuppetBrain. Над героем в авто — подпись намерения мелким текстом («охота», «бегство»…).

## 4. Задел монетизации: «Наследие прошлой жизни» за просмотр рекламы
ВАЖНО: никаких рекламных SDK, сети и платёжных библиотек (это отдельное решение владельца). Только архитектура + заглушка.
- Domain: `LegacyPack` — что можно перенести из прошлой жизни: 30% ресурсов на момент смерти (по каждому виду), один открытый
  в прошлой жизни узел эволюции на выбор (не способность `split`), стартовая масса +15% от пика прошлой жизни (не больше +3).
  Снимок делается при смерти (`RunState.MakeLegacy()`), хранится в SoulMeta (сериализация как у остальных полей), сгорает,
  если начата следующая жизнь без него. Применение: `new RunState(...)` + `ApplyLegacy(LegacyPack, string chosenNode)`.
  Ограничение: не чаще 1 раза за жизнь; счётчик в SoulMeta.
- Systems: интерфейс `IRewardedAds { bool IsAvailable { get; } void Show(System.Action<bool> onDone); }`,
  `AdsService.Current` (по умолчанию `StubRewardedAds`). Заглушка: полноэкранная панель «Здесь будет реклама» с таймером 5 с и кнопкой
  «Закрыть» после таймера → onDone(true); кнопка «Отмена» → onDone(false). Без сети. Флаг `AdsConfig.RewardedEnabled` (true).
- UI: на экране «Отпечаток жизни» (смерть) — кнопка «Сохранить наследие (реклама)»: показывает, что перенесётся
  (ресурсы, узел на выбор, масса), выбор узла, затем Show(); при успехе — следующая жизнь стартует с наследием и баннером
  «Наследие прошлой жизни принято». Если реклама недоступна — кнопку не показывать.
- Тесты `LegacyTests.cs`: снимок (30%, узел, +15% массы с потолком), применение, раз в жизнь, сгорание, сериализация SoulMeta.
