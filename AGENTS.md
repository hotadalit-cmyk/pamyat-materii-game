# Инструкция для GLM / ZCode / других кодовых агентов

## Приоритеты
1. Новые прямые указания владельца проекта.
2. `00_MANAGEMENT/DECISIONS.md` (утверждённые решения; статусы важны).
3. `02_DEMO/DEMO_SCOPE.md` и конкретный `04_DEV/TASK_BACKLOG.md`.
4. `01_GDD/*.md`, `03_ART/*.md`, `04_DEV/ARCHITECTURE.md`.

## Работа
- Общение по-русски; путь проекта и текущую ветку показывать в самом начале первой сессии.
- **Нельзя** импортировать код, сюжеты, ассеты, сохранения или архитектуру старых проектов ServerClosed / ServerClosed_New.
- Не начинать с «прочитай всё»: читать только релевантные документы и конкретные исходники.
- Одна задача за один запрос. Не создавать соседние системы и не дополнять ТЗ самостоятельно.
- Назвать заранее максимум 3–5 затрагиваемых файлов и план изменений в 3–6 строках.
- Использовать встроенный Unity Physics2D; не писать собственный физический движок для MVP.
- Симуляция и сохранения отдельно от визуализации; тестируемые расчёты без MonoBehaviour.
- UI должен быть масштабируем для landscape телефонов, с учётом safe areas.
- Нельзя: `git reset --hard`, `git clean -fdx`, `push --force`, удаление тестов, массовые переформатирования, установка случайных пакетов, изменение main без задачи.
- Не добавлять сеть, платёжные SDK, рекламу, онлайн-регистрацию, сторонние API или модели ML без утверждения.
- Не открывать и не публиковать ключи, пароли, подписи, личные файлы, APK в Git.
- Проверить вначале git status; при чужих изменениях — не затирать.

## Экономия лимитов
- Не запускай полный аудит репозитория на каждый запрос.
- Одна целевая компиляция/тест после изменения; дополнительный прогон только если есть ошибки или затронута критичная система.
- Не выполняй циклы автоматического рефакторинга и самопроверки без ограничения. После двух неудачных попыток остановись с точным логом и гипотезой.
- Отчёт максимум 15 строк: сделано, файлы, реально запущенные тесты PASS/FAIL/NOT RUN, ограничения, коммит.
- Не объявляй NOT RUN как PASS. Не выдавай модельные оценки производительности за измерения.

## Изоляция
- Новый проект имеет свой Git-репозиторий, Android package name, `persistentDataPath` и Unity-проект.
- Только ветки feature/* или task/* для изменений, merge — после обзора.
